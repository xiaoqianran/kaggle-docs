# 为 kagglehub 做出贡献

首先，感谢您抽出时间做出贡献！

我们鼓励并重视所有类型的贡献。

## 问题

我们使用 GitHub issues 来跟踪 **公共** 错误和功能请求。请确保您的描述清晰并且有足够的说明以便能够重现问题。

如果您发现错误或有功能请求，请按照以下说明操作：

* 打开[Issue](/issues/new)。
* 尽可能多地提供有关您遇到的情况的背景信息。
* 提供项目和平台版本（python、pip、kagglehub），具体取决于相关内容。

## 拉取请求 (PR)

我们鼓励每个人先提出一个问题，讨论一般方法，然后再提出 PR 以减少流失。如果您发现的错误的解决方案很简单，我们也直接接受 PR。

创建 PR 时请遵循以下最佳实践：* 使用**清晰且描述性的标题**。
* 如果您的 PR 添加了面向用户的功能或修复了错误，请确保在 [CHANGELOG.md](CHANGELOG.md) 的“下一个版本”部分下添加一个条目
* 如果您的 PR 解决了特定问题，请将 `Fixes #<ISSUE_NUMBER>` 添加到您的 PR 描述中。
* 包括修复前后行为的屏幕截图/控制台输出。
* 包括有关如何重现问题和测试修复的说明。
