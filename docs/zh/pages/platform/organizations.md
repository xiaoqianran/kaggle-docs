# 组织

***

### 概述

任何人都可以在 Kaggle 上创建组织资料。组织资料允许社区中的任何人在一个地方找到您组织的数据集、模型和竞赛。

在创建组织之前，了解组织配置文件的工作原理会很有帮助。

***

### 组织档案如何运作

#### 组织有什么用？

组织简介是组织已发布的竞赛、模型和数据集的“登陆页面”。例如，它为您提供了一种简单的方法来共享（以及其他用户查找）您的团队通过单个链接发布的所有数据集和模型。

#### 组织不适合做什么？

组织不应该被用作与一群人协作的工具。为此，您应该使用 [Kaggle groups](/groups)。

注意：虽然组织的所有成员都可以作为组织创建竞赛、数据集和模型，但这并不赋予组织的其他成员管理该内容（编辑、删除、更新或查看私有资源）的能力。请阅读下面有关组织权限的更多信息。

#### 谁应该创建和使用组织档案？对于研究实验室，无论是大学还是行业公司的一部分，组织配置文件都提供了一种组织团队在一个地方发布的模型和数据集的方法。对于大公司，组织简介将显示您主办的所有比赛。

对于教授，我们建议使用 [Kaggle group](/groups) 来更轻松地查看和管理您在课堂上共享的数据集、笔记本和模型。

***

### 创建新的组织配置文件

#### 创造

任何拥有 Kaggle 帐户的人都可以请求创建组织资料。要开始此过程，请登录您的 Kaggle 帐户，然后填写 [new Organization request form](https://www.kaggle.com/contact#/organizations/request-creation)。

您需要提供以下信息：

- **名称**：您的组织的名称
- **URL**：您应该将其编辑为简短的内容。指向该组织页面的所有链接都将以该 URL 开头，例如其拥有的任何数据集或模型。
- **审核详细信息**：您分享的某些信息不会出现在您的组织资料页面上，但我们的团队将使用它来审核您的组织以供批准。例如，证明您的组织存在于 Kaggle 之外、您组织的目的以及您在组织中的角色。创建组织资料页面后，您将能够在组织资料页面上设置以下内容：

- **概述**：您的组织的“简介”或详细描述
- **标语**：您组织的简短描述
- **网站**：您的组织网站的 URL
- **图像**：您的组织徽标的 400 x 400 像素图像

您还可以在组织资料页面上自由更改或更新组织的大部分详细信息，以及邀请成员加入您的组织等。

完成新组织申请表后，您的组织将在创建之前由 Kaggle 团队审核并获得批准。继续阅读下一部分“回顾”，了解有关后续步骤的更多信息。

#### 回顾

Kaggle 团队正在审核您的组织，请耐心等待。

如果您对审核流程有疑问或想对审核提出申诉，请参阅我们的联系页面：https://www.kaggle.com/contact#/other/issue

#### 批准一旦您的组织获得批准，您将收到电子邮件和/或站点通知。您和组织的其他成员现在可以创建组织拥有的数据集、模型或竞赛，包括将其公开。任何人都可以查看您组织的个人资料页面。

***

### 组织成员权限

#### 组织成员的能力

组织成员可以在批准的组织配置文件下创建数据集、模型和竞赛。

同样，组织目前并不打算用作与一群人协作的工具。虽然组织的所有成员都可以作为组织创建竞赛、数据集和模型，但这并不赋予组织的其他成员管理该内容（编辑、删除、更新或查看私有资源）的能力。

如果您想共享组织配置文件拥有的私有数据集或模型，则需要使用协作功能。

同样，组织成员无法看到任何未启动的竞赛，除非其用户是竞赛的创建者。除非组织所有者共享唯一的邀请链接，否则成员将无法向组织添加新成员。

#### 组织管理员的能力

组织管理员与组织成员具有相同的能力和权限。此外，他们还可以添加和删除成员、将组织的所有权转让给其他成员以及编辑有关组织的信息（徽标、标语、描述等）。

***

### 作为一个组织如何创建内容

#### 比赛

任何人都可以举办社区竞赛，只需点击 Kaggle 任何页面左上角的“+创建”按钮并选择“竞赛”即可。要将您的竞赛与您作为管理员或成员的组织资料关联起来，只需从“创建为”下拉列表中选择您的组织即可。

在组织资料下创建竞赛时，竞赛将带有您组织的徽标，并且竞赛将显示在组织资料页面的“竞赛”选项卡上。当在组织资料下创建竞赛时，谁可以查看或管理您的竞赛不会发生任何变化。也就是说，组织的其他成员无法看到未启动的竞赛，也无法在竞赛启动后管理竞赛的设置。

#### 数据集和模型

任何人都可以发布数据集或模型，只需单击 Kaggle 上任何页面左上角的“+创建”按钮并选择“数据集”或“模型”即可。为了将您的数据集或模型与您作为管理员或成员的组织配置文件相关联，只需从“创建为”下拉列表中选择您的组织即可。

在组织资料下创建竞赛时，数据集或模型将带有您组织的徽标，并且数据集或模型将分别显示在组织资料页面的“数据集”或“模型”选项卡上。当在组织配置文件下创建数据集或模型时，其他成员将能够在其私有状态下看到它。谁可以查看或管理在组织配置文件下创建的数据集或模型，没有任何变化。也就是说，组织的其他成员不能编辑、删除或更新数据集或模型，除非他们在数据集或模型的“设置”选项卡上单独添加为编辑协作者。

#### 将资源转移到组织

您可以将您拥有的资源的所有权转让给您所属的任何组织。只有资源的所有者才能转让所有权。要转移所有权，请导航至资源的详细信息页面并选择“设置”选项卡。向下滚动到“共享”部分，然后单击“转让所有权”，选择要将资源转移到的组织，然后单击“完成”。将所有权转移给组织是不可逆转的。

### 组织模型门控

#### 什么是门控模型门控模型是 Kaggle 上的一种模型，要求用户同意特定协议并可能提供信息，然后才能访问它。该协议可以包括使用条款、隐私政策链接和收集用户数据的表格。

#### 使用模型门控

要使用模型门控，请首先联系 Kaggle 以获得您组织的权限，然后使用模型的编辑者权限登录。在“设置”选项卡上启用模型门控并自定义门控协议，指定审核模式（自动或手动）、隐私策略 URL 以及 YAML 格式的协议内容，其中包括标题、描述和用于收集用户信息的字段。有关如何使用 YAML 创建协议的更多详细信息，请参阅[this page](/model-gating-json-schema)。

启用门控后，通过 UI 或 API 管理用户同意。该 API 允许列出和审查同意，按审查状态和数据过期进行过滤。可以批准或拒绝同意，并且可以根据您的隐私政策在过期之前下载用户数据。访问门控模型的用户将被提示同意并提供信息，并显示他们的访问状态。

#### 控制发布者 API以下 HTTP 端点的基本 URL 是 [https://www.kaggle.com](https://www.kaggle.com)。授权标头使用[HTTP Basic auth](https://en.wikipedia.org/wiki/Basic_access_authentication)：`Authorization: Basic <base64-encoded-token>`。可以使用 [your Kaggle user settings page](/settings) 生成的用户名和密钥创建 *base64-encoded-token* 令牌。用于授权的用户名还必须是您在 Kaggle 上的组织的成员。
